FORMA — COMPONENT SYSTEM AND VARIABLE-DRIVEN PROTOTYPE

IMPORT AND PRESENT

Import the current Forma.fig. If using the ZIP, extract it first. A previously
imported file is a copy; it does not automatically receive repository changes.
Inter and Space Grotesk fonts and SIL licenses are included in fonts/.

1. Open “03 / Desktop” or “04 / Mobile”.
2. Select “Desktop workout” or “Mobile workout” in Present.
3. Choose body regions on the map or chips, then time and equipment. Scroll the
   builder to the plan. All 762 nonempty combinations use the website planner.
4. Start; complete three sets per exercise. The chosen duration gives 4, 6 or 8
   exercises. An empty area selection disables Start.
5. Rest counts down every second. Add 15 seconds repeatedly, skip, or wait.
6. Finish the last set, save, build again, or return through History. End workout
   returns to the builder. History has an empty state before the first finish.
7. Click a movement row, or Exercise guide & video during a set. The guide
   follows that exact exercise. Close returns to the previous screen. Native
   links open the matching YouTube demo and wger source in a browser tab.

The summary shows planned minutes, not elapsed Present time. Saving changes
prototype state for this presentation session; it does not write browser data.
The website measures elapsed time and implements persistent browser storage.
Guide descriptions are attributed wger snapshots retrieved on 20 October
2026. Live API calls and embedded video playback run in the website, not in
the native Figma prototype. The site uses the same reviewed source/video IDs.

DESIGN SYSTEM

00 / Start here       Overview
01 / Foundations      Palette and type guidance
02 / Components       Native component library and linked artwork
03 / Desktop          Builder, workout, rest, summary, history and logic frame
04 / Mobile           The same flow in 390 × 844 scrolling viewport frames
05 / States           Empty, ready and storage-error reference screens
06 / Flow & handoff   Product flow and source-code mapping

Native components:
- Button: Intent and State variants, with an editable Label property.
- Choice: selected/unselected variants and Label.
- Exercise row: Desktop/Mobile sizes; Title, Prescription and Index properties.
- Illustration: Exercise and Size variants; native vector art and instances.
- Metric: Desktop/Mobile sizes; Value and Label properties; Auto layout.
- Brand: shared Forma mark instances.
- Movement guide / Details: Desktop/Mobile variants, Description and
  Attribution text properties, Auto layout and bound prototype variables.

Native variable collections:
- Forma / Primitives: palette, spacing, radii, font families, sizes and leading.
- Forma / Semantic tokens: aliases for surfaces, text, actions, borders and status.
- Forma / Prototype state: selections, plan data, set progress, timer and save.

Colors, borders, corners, layout gaps/padding and typography are bound to
variables. Fourteen shared text styles define the type hierarchy. Lists,
controls, metrics and mobile plan content use Auto layout. Repeated artwork
and controls remain linked instances; text remains native editable TEXT.

The small “Update plan / conditional logic” frame runs a decision tree and
returns to the builder. The two rest frames alternate once per second to drive
the native countdown. They share the same state variables and controls.

VERIFICATION

validation.json records the native inventory and rendering checks.
prototype-validation.json records simulation of the decoded exported actions:
1,524 combinations (762 per viewport), 26 guide/video/source checks, full workouts, countdown/extension,
skip, completion and save. Native glyph data, instance text, variable aliases,
component properties, token bindings and navigation destinations are checked.
Previews are rendered from the reopened .fig file.

These checks do not run the Figma presentation engine. The linked Figma editor
was not accessible to this session; native import/Present still needs checking.
The local export does not update the existing cloud document by itself.

REBUILD

  npm run design:build

The optional design toolchain uses an installed OpenPencil CLI. Set
OPENPENCIL_MODULES to its node_modules directory if installed elsewhere.
No toolchain, backend or build step is needed to publish the website itself.

Sources:
- build-figma.mjs: screen drawing and export orchestration.
- lib/design-system.mjs: tokens, shared styles and linked component instances.
- lib/prototype.mjs: native component variants and properties.
- lib/prototype-model.mjs: variable state and conditional actions.
- lib/functional-prototype.mjs: controls, state bindings and viewport layouts.
- source/exercise-guides.js: attributed guide snapshots for native prototyping.
- lib/figma-export.mjs: native glyphs, variables and reaction serialization.
- validate-prototype.mjs: tests against the exported native action payload.

Rebuilding replaces generated files. Preserve manual Figma edits separately.
